# PLAN — 옵션 만기 알림 시스템

작성일: 2026-11-08 · 상태: 설계 확정, 구현 전

## 1. 왜 만드는가

만기일(매월 둘째 목요일)에는 종가 단일가(15:20~15:30)에 수급이 몰려 코스피200 종가가
접속매매 마지막 가격과 크게 달라질 수 있습니다. 이 움직임은 대부분 **만기 전 1주일 동안
쌓인 포지션**(외국인 선물, 차익 프로그램 잔고, 콜/풋 미결제약정)에서 예고됩니다.
그런데 이 정보는 여러 화면에 흩어져 있어 매번 손으로 모으기 어렵습니다.

목표는 하나입니다. **"이번 만기에 어느 쪽 수급이 종가를 어디로 밀 가능성이 큰가"**를
전주 금요일부터 만기 당일까지 매일 한 장으로 받아보는 것.

## 2. 범위

### 포함 (1차)
- 코스피200 **옵션 월물 만기** (매월 둘째 목요일) 및 **분기 동시만기** (3·6·9·12월)
- 코스피200 **위클리 옵션** 만기 (매주 월·목) — 월물보다 가벼운 알림
- 전주 금요일(D-6) 사전 브리핑 → 월·화·수(D-3~D-1) 일일 포지션 현황 → 만기일(D-0) 당일 알림 → 다음날(D+1) 리뷰
- 겹치는 일정 체크: 코스피200 정기변경(6·12월 동시만기일 종가 적용), MSCI·FTSE 리뷰, 대형 ETF 리밸런싱
- 텔레그램 알림 + 로컬 파일 기록

### 제외
- 자동 주문, 포지션 추천, 손익 계산
- 개별 주식선물·주식옵션 (동시만기 때 "존재"만 언급)
- 야간 시장(유렉스 연계) 데이터

## 3. 전체 그림

```
[일정 엔진] 만기일·휴장일·겹침 일정 계산 (scripts/expiry_calendar.py 확장)
     │
[수집 엔진] KIS API → (실패 시) KRX 정보데이터시스템 / 네이버 금융
     │        외국인·기관 선물/옵션 매매, 미결제약정, 베이시스, 프로그램 매매, 현물 수급
     │
[해석 엔진] DESIGN.md 4장의 규칙표 적용 → 관점(상방/하방/중립) + 근거 3줄 + 주의 1줄
     │
[알림 엔진] 텔레그램 봇 sendMessage, 하루 1~3회 (DESIGN.md 5장 템플릿)
     │
[기록]      data/YYYY-MM/positions.csv, alerts/YYYY-MM-DD.md (D+1 리뷰에 사용)
```

## 4. 단계별 로드맵

| 단계 | 내용 | 완료 기준 | 예상 작업량 |
|---|---|---|---|
| 0. 설계 | 이 문서 3종 + 캘린더 스크립트 | 사용자 검토 완료 | 이번 세션 |
| 1. 일정·알림 뼈대 | 캘린더 운영화(휴장일 API), 텔레그램 봇, 수동 입력으로도 알림 발송 | 만기 D-6/D-3~D-0 알림이 텔레그램에 도착 | 반나절 |
| 2. 수급 수집 | KIS API 인증, 필요한 조회 항목 매핑, 보조 소스 대체 로직 | DESIGN.md 3장 항목이 CSV에 매일 저장 | 1~2일 |
| 3. 해석 규칙 | 규칙표를 코드로 옮기고 관점 문장 자동 생성 | 알림에 "관점 + 근거 + 주의" 자동 포함 | 1일 |
| 4. 운영 자동화 | 스케줄 실행(GitHub Actions 또는 PC 작업 스케줄러), 실패 알림 | 손대지 않아도 한 달 치 알림이 옴 | 반나절 |
| 5. 리뷰 루프 | D+1 자동 리뷰(예상 vs 실제), 월별 적중 기록, 규칙 가중치 수정 | 3개 만기 이상 기록 누적 | 지속 |

첫 실전 목표: **2026-12-10 동시만기** (D-6 = 12-04 금). 그 전 2026-11-12 월물 만기는
수동 입력 + 알림 뼈대(1단계)만으로 리허설.

## 5. 핵심 결정과 근거

| 결정 | 선택 | 이유 | 대안 |
|---|---|---|---|
| 데이터 소스 | KIS API 기본 | 계좌만 있으면 무료, 자동화 적합, 휴장일 조회도 제공 | KRX 정보데이터시스템(로그인 불필요, 구조 변경 위험), 네이버 금융 |
| 알림 | 텔레그램만 | 가장 단순, 이미 사용 중 | 노션 기록은 2단계 이후 필요 시 |
| 범위 | 월물 + 위클리 | 사용자 요청 | 위클리는 "가벼운 알림"으로 부담 최소화 |
| 실행 환경 | GitHub Actions 권장 | PC를 켜둘 필요 없음, 저장소가 이미 있음 | PC 작업 스케줄러(간단하나 PC 꺼지면 중단) |
| 기록 | 로컬 CSV/마크다운 | 리뷰 루프에 충분, 의존성 없음 | 노션 DB |

## 6. 리스크

- **KIS API가 선물옵션 투자자별 매매동향을 제공하지 않을 수 있음** → 2단계 첫 작업에서 확인. 없으면 KRX 정보데이터시스템 화면 다운로드로 대체(DESIGN.md 7장).
- **데이터 공표 시차**: 프로그램 차익잔고 등은 장 마감 후 늦게(또는 다음날) 공표 → 알림 시각을 데이터 도착 시각 뒤로 둠.
- **휴장일·규정 변경**: 하드코딩 휴장일은 임시. 운영 전 API 또는 KRX 공지로 교체.
- **해석 규칙의 과신**: 규칙은 "가능성 높은 쪽"을 말할 뿐. 알림마다 반대 시나리오 1줄을 반드시 포함.
